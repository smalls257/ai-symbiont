## Question

T39 measured adaptation over parallel attempts at the same task. This run asks the owner's question instead: after a repository's tasks 1..k, does a network warn better on task k+1, a new issue? Two techniques are under test, each for the fly ("fly combined", T48) and the home-grown DenseNet ("DenseNet combined", T48):

1. A MAML-style meta-learned start: only the readout's starting weights and an online calibrator (scale, bias) are meta-trained; wiring and rates are fixed.
2. Broad pre-training plus a few-shot fine-tune.

Counters and the logistic classifier, the live warner, are the references. No claim about how fast anything learns beyond "adapts within the first 10 tasks" [established]. The fly is "a learner built on the fly's real circuit".

## Protocol

Learn from tasks 1..k, score task k+1, for k = 0, 1, and so on. A network decides every step of a task with its state after the previous task. It then learns that task's outcomes with its own rule: the fly's dopamine rule, or DenseNet's delta rule (rate 1 decaying as 1/(1 + updates/20,000)). The calibrator then steps through those outcomes at rate 0.05 per step, the rate T39's validation chose [measured]. Nothing is learned within a task (`symbiont.eval.meta2_replay.sequential_risks`). The false-alarm cost is 0.5 in every loss and rule [established].

## Rows (one registered row each; settings pinned)

| row | role | what it is |
|---|---|---|
| warn never; a note at every allowed step | floor | by construction |
| counters | reference | `Counters(min_count=1)` through the real replay, from empty history per repository. Note: counters learn within a task, as the replay does |
| logistic own tasks | reference | class-weighted logistic regression (L2 1000) refit after each task on tasks 1..k only; silent until it has seen both labels |
| logistic broad | reference | the same classifier fit once on every training step, frozen |
| logistic broad + refit | reference | the broad fit refit after each task on tasks 1..k toward its own coefficients (prior strength 10, the T47 R2 rule) |
| {fly, DenseNet} cold | under test | the network's fresh start, calibrator (1, 0), online rule |
| {fly, DenseNet} MAML start | under test | meta-trained start, then the same online rule |
| {fly, DenseNet} broad | under test | readout and calibrator fit on every training step, frozen (no online rule) |
| {fly, DenseNet} broad + fine-tune | under test | after each task, the broad weights fine-tuned on tasks 1..k with a fixed Adam step budget (rate 0.01), then frozen for task k+1 |
| {fly, DenseNet} in-domain | ceiling | the broad weights fine-tuned for 300 steps on all of the repository's other tasks, future ones included (5 task folds); never a candidate |

**MAML training.** The outer loop runs Adam over the start, with the gradient norm clipped to 1. Each outer step draws a meta-batch of 16 training repositories [established]. The inner loop unrolls the network's own rule over a repository's first 10 tasks [established] in torch. The outer loss is the false-alarm-weighted log loss of every task decided along the way, so the gradient is exact and second order [established]. The torch rule is checked against the numpy rule one task at a time from the numpy state before any job runs: the largest gaps were 3e-16 (fly) and 1.5e-11 (DenseNet) [measured]. Training ran 200 outer steps with checkpoints every 25, at outer rates 0.001 and 0.01 [established].

**Pinned settings,** chosen on the validation repositories by early-window value at the primary price, never by loss (`results/meta2-settings.json`, sha256 `267f2ae1e7cf6520313683992484e3362a25a090c48eba6abb933a59c53ca688`, which pins the sha256 of each start file it loads; the start files stay under the run directory, outside git):

## Metrics

- Option A at the primary price: a true warning +1, a false warning -0.5, a true heads-up +1, a false heads-up -0.25. Notes go only at boundary steps, at most 2 per session, and none within 5 steps of the last.
- **Primary:** net value per 100 steps over the early window (each repository's first 10 tasks), pooled over the 12 held-out repositories. The interval is the 95% percentile interval from 2,000 task-bootstrap draws within each repository (numpy seed 20261029), with the same draws for every row, so differences are paired [established].
- Network rows are seed means of per-task counts over wiring seeds 0, 1, 2.
- **Secondary (reported, never decides):** the late window (task 11 on) and all tasks; each repository on its own; precision and the notes per session that `note_cost_report.scored` prints.

## Decision rule (exact, primary price, pooled, early window)

Each named difference is written `better` only if its paired interval lies entirely above 0, `worse` only if entirely below, and `tie` otherwise. The report's first line per question is that word and the interval.

1. **MAML (per network):** MAML start minus cold. The technique helps on new issues only if this is `better`.
2. **Fine-tune (per network):** broad + fine-tune minus broad, as above.
   - The share of the in-domain gain recovered, (fine-tune - broad) / (in-domain - broad), is reported only if in-domain minus broad is `better`.
   - Otherwise the report says "no measurable in-domain gain to recover".
3. **The classifier reference:** every under-test row minus logistic own tasks and minus logistic broad + refit. A network row "matches the live warner" only if neither difference is `worse`, and "beats" it only if both are `better`.
4. **Counters:** every under-test row minus counters, printed beside each row.
5. **The network slot:** among the six under-test network rows whose pooled early-window interval lies above 0, the row with the highest point estimate names the slot's network.
   - If the best fly row minus the best DenseNet row is `tie`, the slot stays with the fly ("not distinguishable at this size").
   - If no network row earns, the slot is empty.
   - The live warner stays the classifier unless rule 3 says "beats".
6. No re-run after seeing the table, and no change of data, settings, thresholds, prices, budget, cooldown or rule.

## Hypotheses (not claims)

Validation numbers below are exploratory and in-sample: the settings and thresholds were chosen on the same 10 repositories, `results/meta2-exploratory.json`.

- [hypothesis] The MAML start helps the fly and DenseNet a little in the early window and not after. On validation, MAML minus cold was 0.033 [0.005, 0.064] for the fly and 0.038 [-0.025, 0.094] for DenseNet early, and -0.004 and 0.008 late [measured].
- [hypothesis] The fine-tune ties broad. Validation: fly -0.005, DenseNet 0.015 early [measured]. In-domain minus broad was near 0 early, so the share is expected to be undefined.
- [hypothesis] No network row is distinguishable from the classifier early. Validation: every network row minus logistic own tasks was `tie` early [measured].

## Disclosures

- The selected MAML checkpoint is the maximum of 18 noisy early-window values per network (validation curves moved by about 0.03 between neighboring checkpoints [measured]), so the validation gain is biased upward (winner's curse).
- The counters row chose threshold 0, a heads-up at every allowed step. Its early value (0.146 on validation [measured]) is therefore the "heads-up wherever allowed" baseline, and most rows sit within 0.07 of it early [measured].
- Free-running, DenseNet's rate-1 rule is chaotic: summation-order rounding grows to a whole probability within ten tasks [measured]. The torch check is therefore per task from the numpy state. The scored numbers come from the numpy rule.
- The exploratory results file names code commit `2bc451c`. The run used the working tree that became `c4f54ec`, which adds the per-task check, the gradient clip and the scored step [established].
- The scored step was smoke-run with the validation repositories standing in for held-out ones. It reproduced the exploratory table exactly from the pinned settings and saved starts [measured]. No held-out label was built.
- The calibrator rate (0.05) and classifier L2 (1000) were fixed from earlier runs (T39, T46), not tuned here.

## Known limits

- 12 repositories and 120 early-window tasks [measured]. With no multiplicity correction across the many named differences, only the rules above decide.
- Heads-ups only: the warning tier is priced but never used [measured].
