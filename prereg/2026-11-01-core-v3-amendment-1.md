# Core v3 (v3.1): amendment 1, STaR data replaces the v3 training set; test set, servers and stopping rules

Dated 2026-11-01, committed before the training starts. v3 was never trained. The 15-row smoke pilot failed on a setup limit (15 steps are not more than the warmup), so it has no result and is exploratory only. This amendment replaces v3's training set and adds the rules below; the question, arms, primary measure and verdict words of `2026-10-31-core-v3.md` stand.

## Training data: real solved runs plus rationalized (STaR) runs [measured]

- **Real runs.** The 32 solved Glimmer runs of the v3 prereg (20 tasks), each weighted twice by repetition in the training file. [measured]
- **STaR runs.** Plain Glimmer in the normal mini-SWE-agent loop on sqlglot and PennyLane tasks with eval images, with a hint block giving the reference (gold) patch appended to the task and the instruction "Use this reference only to guide your investigation. Never mention or quote it; reason and act as if you are discovering the fix yourself (inspect the code, reproduce, edit, verify)". Tasks exclude the 60 test tasks, the v3 train tasks and every task with an earlier Glimmer run, and come in the order of sha256(`core3-star:<id>`). Only runs the grader marks resolved count. Generation ran from 2026-10-31 18:06 to 2026-11-01 06:00 PST on the Strix, the 5080 and the laptop (plain Glimmer, no adapter). It attempted 107 tasks and resolved 54. A first wave lost most of its tasks to image-pull timeouts and was rerun after the pull was made a separate step; no second attempt reached a kept run. [measured]
- **Hint stripping and sanitizing.** The hint block is removed from the task text in every training row. In each resolved run, every sentence or line in the reasoning and text that refers to the hint is deleted. The patterns are: reference patch/solution/fix/diff/implementation, "the reference", gold patch, provided/given/supplied patch, "the hint(s)", "hint block". A run is kept only if no reference remains (a reference in a command cannot be edited out, so that run is dropped) and at least half of its assistant steps still have reasoning. Result: **52 kept of 54 resolved (2 dropped, 3.7%, both for a reference in a command)**. [measured]
- **Disclosure.** The STaR reasoning was written with the answer visible; mentions were removed by rule, but specific details of the fix may remain in it. Training-data construction cannot leak into the test, because the 60 test tasks are fixed, disjoint and listed before training.
- **Rows.** Windows of up to 3,500 tokens around the last two edits and the final submit of each run, Glimmer's own reasoning in the thinking slot, loss on assistant turns only. After holding out validation tasks: **278 training rows, 763,243 tokens, 150,234 trained tokens** (file sha256 `76b75d6b1ea131f455964a7824a23e6c1106f2b11969b44f944796079bf7f5d9`). [measured]

## Training

- Same LoRA recipe as v2 (rank 64, batch 1, 16k window) with these changes: **2 validation tasks held out** (6 validation rows, sha256 `dee82673e6ec4eaaf7e4d2152e08b5eff7c75c1fea2bd1ad3f3aba9835b2133a`); **half the learning rate** (peak 5e-5 and floor 5e-7, against 1e-4 and 1e-6); **2 epochs** with the held-out loss evaluated at the end of each epoch and the best checkpoint kept as the adapter. The manifest's sha256 is `b6e378ef5d6a491d5694ea9a7256baed3fb579b20f47cc35c2ecdba001b03cb4`. One adapter, `Muse-Glimmer-30B-v3-self`; its GGUF hash is added by a dated amendment before the first test run [established].

## Test

- **Tasks.** The 60 non-Django tasks of `results/core-v3-test-set-2.json` (sha256 `391bd873f27e96b0a7ffb2c9d6a5f1a6c7af1c302ef2895ca17bc5a18caf3593`; sqlglot 42, PennyLane 18), in the order of instance id, so the analysis uses completed blocks in that order [established].
- **Cutoff moves to Mon 2026-11-02 12:00 PST** (UTC-8); no new task starts after it. The primary, the verdict words and the secondary are unchanged [established].
- **Servers.** The Strix router (presets `plain64` and `v3-self`, 64k per slot) and the 5080 (llama.cpp with the adapter loaded and per-request LoRA scales, plain and v3 on one server). The adapter must apply there: its greedy output must differ from plain and the file hash must match the Strix file. A block's plain and v3 runs both run on the **same server**, the server is recorded per block, and tasks are claimed in id order by whichever server is free. The laptop stays out because its build cannot apply a LoRA correctly [established].
- **Futility look.** One pre-planned look after 20 completed test blocks: if V3 minus plain (paired by task, 95% bootstrap interval, seed 20261101) has an upper bound below 0, the test stops and is reported as "stopped for futility". It can never declare an early win [established].
- **Reasoning-collapse abort.** Before the test, the final adapter and plain each generate greedily on 3 train-task prompts. If the median reasoning length of the adapter is under 50% of plain's, the test is aborted [established].
- **Slot trial.** Raising the Strix plain preset from 6 to 8 slots gave 13,618 against 13,926 decode tokens in 10 minutes (-2%) and was reverted; 6 slots stay [measured].
