# Declaration: extra held-out maps generated with OBLIGE

**Declared 2026-10-29, before any smoke, walker or model run on a generated map.** Generated maps are held out in full: no model, card, lesson or tuning step touches them until a frozen prereg names them. This file fixes the recipe and the keep rule. A later change is a new dated file.

Claim tags: [measured] = observed in our own run, [established] = known from the literature or the code's own documented behavior, [hypothesis] = a guess the run can support or refute.

## Why

The project plays Freedoom via ViZDoom; the generated maps are Doom 2 format data files for that game.

The two Freedoom games give 13 held-out maps that pass the smoke test. A map-level interval over 13 maps is wide. Generated maps add more, different maps for the across-maps interval [hypothesis].

## The tool

- OBLIGE Level Maker 7.70 by Andrew Apted and contributors, as bundled in PyOblige (https://github.com/mwydmuch/PyOblige, commit e028d32, 2018). OBLIGE is GNU General Public License version 2 or later (`GPL.txt` and the README of that source) [established]. It is an external tool: built and run outside this repository, never vendored. The generated WADs stay under `~/symbiont-runs/oblige/wads` and are never committed (`*.wad` is ignored); a Doom 2 format map is a data file the tool produces, not a copy of the tool [hypothesis; the license of generated levels is not independently checked here].
- Build on macOS arm64 (a one-time local step): `brew install fltk jpeg-turbo`; in `pyoblige/Oblige_src` change the FLTK check in `gui/ui_window.cc` from `FL_MINOR_VERSION != 3` to `FL_MINOR_VERSION < 3` (FLTK 1.4.5 is installed, the source asked for 1.3); delete the stale x86 `Oblige` binary the repository ships; `make -f Makefile.macos LDFLAGS="-L/opt/homebrew/opt/jpeg-turbo/lib"`. Batch mode: `Oblige --batch out.wad --load config.txt --keep`, driven by `scripts/evolve/generated_maps.py generate`.
- The IWAD is `freedoom2.wad`. Each generated WAD holds one map named MAP01 and loads in ViZDoom as a PWAD on top of the IWAD (`set_doom_scenario_path`); loading was checked on one test map before this declaration [measured].

## Keep rule (applied in seed order, no cherry-picking)

A map is kept if all three hold, checked without any model:

1. the static route check passes from the player 1 start to an exit with every key held and every door open (the same function as the Freedoom smoke test);
2. the engine loads the map;
3. the scripted walker (`go_to(exit)` with every key held, monsters removed, the player invulnerable; the same walker as the Freedoom route check) reaches the exit within its decision limit.

The first 40 maps that pass, by id, are kept; if fewer than 30 pass the generated set is reported as too small to use as a gate. The kept list and the stage at which each other map failed are written to `results/evolve-generated-maps.json`, counts and ids only. A map that fails is dropped and listed, never replaced or regenerated.

## Exposure

The check plays each map once with the scripted walker and no model. Nothing is tuned on it. Spark does not see a generated map before a frozen prereg names the kept list.
