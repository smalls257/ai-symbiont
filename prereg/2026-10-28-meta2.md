## Question

T39 measured adaptation over parallel attempts at the same task. This run asks the owner's question instead: after a repository's tasks 1..k, does a network warn better on task k+1, a new issue? Two techniques are under test, each for the fly ("fly combined", T48) and the home-grown DenseNet ("DenseNet combined", T48):

1. A MAML-style meta-learned start: only the readout's starting weights and an online calibrator (scale, bias) are meta-trained; wiring and rates are fixed.
2. Broad pre-training plus a few-shot fine-tune.

Counters and the logistic classifier are the references; the live warner is the logistic broad fit. No speed-of-learning words beyond "adapts within the first 10 tasks" [established]. The fly is "a learner built on the fly's real circuit".

## Protocol

Learn from tasks 1..k, score task k+1, for k = 0, 1, and so on. A network decides every step of a task with its state after the previous task. It then learns that task's outcomes with its own rule: the fly's dopamine rule, or DenseNet's delta rule (rate 1 decaying as 1/(1 + updates/20,000)). The calibrator then steps through those outcomes at rate 0.05 per step [established] (inherited from T39). Nothing is learned within a task (`symbiont.eval.meta2_replay.sequential_risks`). The false-alarm cost is 0.5 in every loss and rule [established].

## Rows (one registered row each; settings pinned)

| row | label | what it is |
|---|---|---|
| warn never | floor | value 0 by construction |
| a note at every allowed step | floor | every allowed step gets a note at the warning tier; -0.152 early on validation [measured] |
| counters | reference (a heads-up at every allowed step: threshold 0 was chosen on validation) | `Counters(min_count=1)` through the real replay from empty history; learns within a task, as the replay does; printed beside every fly and every DenseNet row |
| logistic broad | reference (the live warner) | class-weighted logistic regression (L2 1000) fit once on every training step, frozen |
| logistic own tasks | reference (per-k refit, the dispatch's named reference) | the same classifier refit after each task on tasks 1..k only; silent until it has seen both labels |
| logistic broad + refit | reference (per-k refit, the dispatch's named reference) | the broad fit refit after each task on tasks 1..k toward its own coefficients (prior strength 10, the T47 R2 rule) |
| {fly, DenseNet} cold | under test | the network's fresh start, calibrator (1, 0), online rule |
| {fly, DenseNet} MAML start | under test | meta-trained start, then the same online rule |
| {fly, DenseNet} broad | under test (the fine-tune's comparator) | readout and calibrator fit on every training step, frozen (no online rule) |
| {fly, DenseNet} broad + fine-tune | under test | after each task, the broad weights fine-tuned on tasks 1..k with a fixed Adam step budget (rate 0.01), then frozen for task k+1 |
| {fly, DenseNet} in-domain | ceiling (uses future tasks; never a candidate) | the broad weights fine-tuned for 300 steps on all of the repository's other tasks (5 task folds) |

Registered network rows are seed means over wiring seeds 0, 1, 2. Per-seed rows are sensitivity.

**MAML training.** The outer loop runs Adam over the start, with the gradient norm clipped to 1. Each outer step draws a meta-batch of 16 training repositories [established]. The inner loop unrolls the network's own rule over a repository's first 10 tasks [established] in torch. The outer loss is the false-alarm-weighted log loss of every task decided along the way, so the gradient is exact and second order [established]. The torch rule is checked against the numpy rule one task at a time from the numpy state before any job runs: the largest gaps were 3e-16 (fly) and 1.5e-11 (DenseNet) [measured]. Training ran 200 outer steps with checkpoints every 25, at outer rates 0.001 and 0.01 [established].

**Pinned settings,** chosen on the validation repositories by early-window value at the primary price, never by loss (`results/meta2-settings.json`, sha256 `267f2ae1e7cf6520313683992484e3362a25a090c48eba6abb933a59c53ca688`):

|---|---|---|---|
| fly combined | 0.001, 150 | 1 | 5 |
| DenseNet combined | 0.01, 175 | 1 | 80 |

Each row's (note, warning) thresholds, per wiring seed, were chosen by the T46 rule on every validation task and are in the settings file. No threshold is refit on a held-out repository [established]. Every chosen pair has no warning tier, so this run measures heads-ups only [measured].

## Primary metric

- **What:** net value per 100 steps at the primary price (heads-up +1/-0.25, warning +1/-0.5), heads-ups only in practice [measured].
- **Window:** the early window, tasks 1 to 10 of each held-out repository, with task 1 scored from the start (k = 0).
- **Pooling:** over the 12 repositories as one sum of value over one sum of steps.
- **Delivery:** notes only at boundary steps, at most 2 per session, none within 5 steps of the last.
- **Interval:** the 95% [established] percentile interval from 2,000 task-bootstrap draws resampled within each repository (numpy seed 20261029), with the same draws for every row, so every named difference is paired.
- **Sensitivity and secondary (never decide):** each repository on its own with the same draws; the late window (task 11 on) and all tasks.

## Decision words

A named difference is `better` if its paired interval lies entirely above 0, `tie` if it includes 0, and `worse` if it lies entirely below 0. The report's first line per hypothesis is that word and the interval.

## Hypotheses (registered; only H1 decides)

- **H1 (primary, one test): fly MAML start minus fly cold, early window, pooled.** [hypothesis] `better`. Expectation: "[measured, exploratory, in-sample, best of 18 checkpoints] +0.033 [0.005, 0.064] on validation; the selection bias is of the order of the gap between neighboring checkpoints (about 0.03), so the expected held-out verdict is `tie`." A `tie` or `worse` is the result, and is reported in those words as the first line of the report.
- **H2 (secondary, same bar): DenseNet MAML start minus DenseNet cold.** Validation was `tie` (+0.038 [-0.025, 0.094]) [measured]; expected `tie`. H2 does not rescue H1: if H1 is `tie` and H2 is `better`, the report says "the technique helped the network it was not expected to help; exploratory until a fresh run".
- **H3 (per network): broad + fine-tune minus broad.** Expected `tie`.
  - The share of in-domain gain recovered, (fine-tune - broad) / (in-domain - broad), is reported only if in-domain minus broad is `better`.
  - Otherwise the report says "no measurable in-domain gain to recover".
- **H4 (per network, the reference check): MAML start minus counters.** [hypothesis] `tie`. This separates "the start learned something" from "a heads-up everywhere is already worth 0.146" [measured, validation].
- **H5: no under-test row beats the live warner (logistic broad) early.** The six under-test rows are cold, MAML start and broad + fine-tune for each network. Expected to hold. A row whose difference from the live warner is `tie` is "not distinguishable from the live warner at this size".

## The network slot

The slot is not decided by point estimates.

- **Eligibility.** A network row (one of the six under-test rows) is eligible only if all three hold:
  - (a) its pooled early-window interval lies above 0;
  - (b) its paired difference from counters is `better`;
  - (c) its difference from logistic broad is not `worse`.
- **Comparison.** The best eligible fly row and the best eligible DenseNet row (highest point estimate; ties broken by the order below) are compared once:
  - `better` for either side names the slot's network;
  - `tie` leaves the slot where T48 left it, with the fly, and the words "not distinguishable at this size", which is a default, not a win.
- If only one network has an eligible row, that network takes the slot, with the words "the only eligible network".
- If no row is eligible, the slot is empty and the report says "counters or the classifier are the warner at this size".
- **Tie order, plainest first:** counters, logistic broad, logistic own tasks, logistic broad + refit, DenseNet cold, DenseNet MAML start, DenseNet broad + fine-tune, fly cold, fly MAML start, fly broad + fine-tune.
- The live warner stays the classifier unless an under-test row is `better` than logistic broad.

## "The meta learner works"

The claim is made only if all three hold on the held-out set:

1. H1 is `better`.
2. The fly MAML row minus counters is `better` (it beats a heads-up at every allowed step).
3. The fly MAML row's difference from the live warner is not `worse`.

Anything less is reported as "a meta-learned start did not measurably help on new issues at this size", with the interval. The runner writes these words, H1 to H5 and the slot (`meta2_scored.verdicts`).

**T20 void trigger.** If T20's placebo arm measures the cost of a wrong heads-up above 0.25 of a right one, every value-based verdict of this run, including H1, is void, and a dated amendment declares the re-scoring.

## Disclosures

- The selected MAML checkpoint is the maximum of 18 noisy early-window values per network: validation curves moved by about 0.03 between neighboring checkpoints [measured].
- Counters chose threshold 0, a heads-up at every allowed step. Its early value (0.146 on validation [measured]) is the "heads-up wherever allowed" baseline, and most rows sit within 0.07 of it early [measured].
- Free-running, DenseNet's rate-1 rule is chaotic: summation-order rounding grows to a whole probability within ten tasks [measured]. The torch check is therefore per task from the numpy state, and the scored numbers come from the numpy rule.
- The exploratory results file names code commit `2bc451c`. The run used the working tree that became `c4f54ec`, which adds the per-task check, the gradient clip and the scored step [established]. The verdict code (`meta2_scored.verdicts`) was added after the exploratory run and before the freeze; it computes words only.
- The scored step has no pytest, because torch is not in the dev environment. Its guards are `run_provenance` and the settings sha256. It was smoke-run with the validation repositories standing in for held-out ones and reproduced the exploratory table exactly from the pinned settings and saved starts [measured]. No held-out label was built.
- The ruling's H1 expectation is quoted with American spelling ("neighboring"), as the spelling gate requires.
- The calibrator rate (0.05) and the classifier L2 (1000) were inherited from T39 and T46, not tuned here.

## Known limits

- **Multiplicity.** H1 is one interval; H2 one; H3 two; H4 two for the MAML rows, six counting every under-test row against counters; H5 twelve (six rows against the live warner and the per-k references); the slot one. That is about 23 intervals at 95%, with no correction [established], plus per-repository and late-window tables. Only H1 decides; the rest fix wording.
- **Optimistic validation.** Selection on 10 validation repositories among 18 checkpoints, 2 outer rates and per-row thresholds means the validation table is optimistic by construction; only the held-out table is evidence.
- **Power.** 120 early-window tasks give an interval half-width of about 0.03 on a paired difference [measured on validation], the size of the effect under test, so `tie` is the likely verdict.
- **A narrow held-out set.** Fresh repositories were chosen from only 22 candidates with 20-plus tasks, so the held-out set is 12 mid-size projects, not the pool.
- **Labels and tiers.** Labels are pool-style, not T46's, so these numbers are not comparable with T46 [established]. Heads-ups only. The in-domain ceiling uses future tasks and is never a candidate [established].
