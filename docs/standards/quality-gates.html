1

Purpose and principle

Gates are the mechanical half of the constitution: each one makes a named Violation un-commitable rather than merely discouraged.

▶
  • Every gate names its Violation. A gate that cannot say which decay it prevents is Paper Tiger tooling: green CI, same rot. The name decides the gate's shape (section 2 shows how).
  • Gates fail closed. A missing binary, a missing config, an empty whitelist file, or a scan run from the wrong directory must exit non-zero. Otherwise the gate is a Silent Fallback: the build looks green because the check never ran. Every checker anchors to git rev-parse --show-toplevel, never to cwd.
  • Fix the gate, never suppress it. No # noqa, # nosemgrep, # type: ignore or whitelist line without owner, reason and expiry (section 4). An undated exception is a Fossil Comment that executes.
  • One definition per gate. The hook, pre-push, and CI call the same script in scripts/gates/. Two spellings of one gate drift into two verdicts, which is a Distributed Monolith in miniature and teaches people to trust neither.
  • Fast gates first. Pre-commit scans staged files only and stays under 15 s; anything slower moves to pre-push. A slow gate in the inner loop is Computational Friction and is bypassed within a week.
  • Stricter in the core. records → miner → core is the pure, airplane-tested center; thresholds there are tighter than in store, readers, eval, service, delivery, scripts. The core is where an Infected Core or a God Method costs the most to undo.

A · Secrets, data and publish (7 gates)
QG-SEC-01 gitleaks v8.30.1, staged files blocking · C
Silent Fallback → Sensor. The gate exits 2 if the gitleaks binary or .gitleaks.toml is missing; a scan that silently "found nothing" because it never ran is the exact failure it exists to prevent. The existing grep fallback in ops/secrets_scan.sh is demoted to a loud warning, never a pass.
Custom rules (appendix): Meta API keys, Hugging Face tokens (hf_…), Glimmer / llama endpoints with embedded tokens, private IPv4 ranges, lab hostnames, home paths (POSIX and Windows), MAC addresses, e-mail addresses (only noreply and example addresses pass) and phone numbers; the built-in rules add GitHub, AWS, Anthropic and OpenAI tokens, private-key blocks and generic high-entropy keys. Waiver: [[allowlists]] entries by path only, each with a comment naming owner, reason, expiry.
QG-SEC-02 gitleaks v8.30.1, full git history blocking · P, CI
Black Box → Sensor. A secret deleted in the working tree still ships in history; only a whole-history scan (gitleaks git .) sees it. Runs before every push (project rule: "secrets scan before every push") and in CI. If history is dirty the fix is a new repo, since the git rules forbid rewriting (no rebase, no amend, no reset); the gate's message says exactly that instead of suggesting a filter-branch.
QG-SEC-03 data, transcript, weights and large-file path guard (scripts/gates/check_paths.sh) blocking · E (by name), C, P, CI, R (on the exported tree)
Leaky Narrative at the repo boundary → Filter; Silent Fallback → Sensor. Fails on any tracked or staged path matching data/, runs/, transcript or trajector names, .traj, *.parquet, *.jsonl outside tests/fixtures/, *.csv/.tsv/.ndjson/.log, weights and adapters (*.gguf, *.safetensors, *.bin, *.pt, *.pth, *.ckpt, *.onnx, adapter_*), *.wad (Freedoom is downloaded on setup, never committed), keys (*.pem, *.key, id_*), archives, *.sqlite, .env*; on a .json outside tests/fixtures/, results/, dashboard/sample/ and the gate baselines; on any file over 1 MB (allowlist: uv.lock); on a fixture over 200 KB; and on a binary that is not an image, font or pdf (a weight under another name). The same script judges an exported directory (check_paths.sh tree DIR). Names are read NUL-delimited and matched case-insensitively one at a time, so a non-ASCII name, a space or an upper-case extension cannot slip past a pattern; a name with a control character, quote or backslash is itself a finding. results/ and dashboard/sample/ may hold .json only. No waiver: a published private transcript cannot be un-published. Exception (QG-FE-01/03 wiring): exactly dashboard/package.json and dashboard/package-lock.json are allowed, as npm's pinned tooling manifests; two exact names, never a pattern, tested.
QG-SEC-04 result-file content (scripts/gates/check_results_content.py) blocking · C, P, CI, R
Leaky Narrative at the repo boundary → Filter. An allowlist of shapes, not a blocklist of key names. A tracked or staged results/*.json or dashboard/sample/*.json is an object whose values are numbers, booleans, null, lists, objects, or strings of at most 120 characters with no newline and at most 12 words; a string with no whitespace (a 0/1 flag string, an id, a hash) may run to 400. The short label fields label, status, source keep the 120-character limit and only waive the word count. The long label fields rule, note, notes, *_note, table, table_rows, caveats, follow_up, result (author-written prose, never a record's text) may hold a sentence of up to 260 characters, and at most 40 such strings per file. Keys follow the same limits. Keys that usually carry text (prompt, content, messages, patch, trajectory, problem_statement, response, output, input, reply, summary, comment, command, question, answer, query, …) are refused when their value is a sentence, list or object. A bare string or list at the top, or a file it cannot parse (exit 2), fails. QG-SEC-03 allows only .json files under results/. No waiver.
QG-SEC-05 owner private terms (scripts/gates/check_private_terms.py) blocking · C (staged lines), P, CI, R
Silent Fallback at the publish boundary → Sensor. A regex cannot know the owner's user name, e-mail local part or LAN host name, and writing them into a tracked config would publish them. They live in ~/.config/symbiont/private-terms.txt (or $SYMBIONT_PRIVATE_TERMS), outside every worktree. The check fails closed (exit 2) when that file is missing or holds no term of four or more characters, and prints path and line, never the term.
QG-SEC-06 edit-time secrets and data guard (.claude/hooks/guard_paths.sh) blocking · E
Silent Fallback → Sensor, earliest stage. The text of every Write, Edit, MultiEdit and NotebookEdit is piped through gitleaks stdin with the repo's .gitleaks.toml, so a key, private address, home path, e-mail or phone number is refused before it reaches the working tree. Missing gitleaks or config denies the write. Weights, datasets (*.jsonl outside fixtures), *.wad and key files are denied by name, case-insensitively.
QG-PUB-01 publish check (scripts/publish/check_export.sh) release · R
Silent Fallback at the publish boundary → Sensor. Exports every file of HEAD with git checkout-index (not git archive, which honors export-ignore) to a temp dir and runs every sensitive-data check on the exported files, not on history and not against a baseline: SEC-03 (tree mode), SEC-01 (gitleaks over every file), SEC-05, SEC-04 and the egress and prompt-logging semgrep rules. The checks and their configuration are those of the exported commit, and the run is refused while a gate file differs from HEAD in the working copy. The exported file count must equal the commit's, and a .gitattributes with export-ignore/export-subst is a finding. A missing src/ fails. Any finding exits non-zero. It runs before the first public push and stays red until the tracked files that still name lab addresses and the history baseline are cleaned.
B · SAST and repo-specific semgrep rules (2 gates)
QG-SAST-01 semgrep 1.182.1 registry packs p/python, p/bandit, p/secrets blocking on ERROR, advisory on WARNING · C (staged), P, CI
Forensic Coding → Anchor. The pin lives in .semgrep/VERSION and the launcher refuses to run any other version, naming both. Unpinned, a registry update changes the verdict with no commit explaining why. Registry packs are fetched once and cached; offline runs use --metrics=off and the cached packs, never a silent skip. Wired as scripts/gates/semgrep_registry.sh (verdict by check_registry_findings.py): changed files in fast, the whole tree in full. Differs from the sketch: the snapshot in .semgrep/registry/ is gitignored, not committed, because the p/secrets pack carries secret-shaped example strings that gitleaks (QG-SEC-01/02, the publish check) rightly flags and the only fix would be an allowlist weakening the secrets gates. scripts/gates/fetch_semgrep_packs.sh fetches it once per checkout and writes STAMP (semgrep version, date, rule counts, hashes), which every run prints; a missing snapshot or one fetched under another semgrep exits 2. INFO findings (bandit B101 asserts) are ignored.

C · Complexity and size (3 gates)
QG-CPX-01 lizard 1.24.3 + AST nesting check, pure core (records, miner, core, routeb) blocking · E, C, P, CI
God Method → Shield. Per-function caps, so the waiver must be per-function too (path.py:function in .lizard-whitelist.txt); ruff's C901 is deliberately not selected because its only exemption is per-file, which would un-cap the whole module to excuse one function. Thresholds: CCN ≤ 10, NLOC ≤ 30, parameters ≤ 5, nesting depth ≤ 3. Nesting is measured by scripts/gates/check_nesting.py on the AST: lizard's -ENS extension warns on every Python function whatever the limit (indentation is not braces) measured on 1.24.3; the field is max_nested_structures, not max_nesting_depth. NLOC is lizard's -T nloc=N, not --length (which counts lines).
QG-CPX-02 lizard 1.24.3, rest of src/ and tests blocking · C, P, CI
Same tool, looser caps: CCN ≤ 12, NLOC ≤ 40, parameters ≤ 5, nesting ≤ 3. Test functions: NLOC ≤ 60. scripts/ and ops/: CCN ≤ 15 advisory. Phase 1 holds changed files to these caps; the whole-tree offender counts live in scripts/gates/baseline.json and the whitelist stays delete-only (section 4).
QG-CPX-03 file and class size (scripts/gates/check_file_length.py) blocking · C, P, CI
God Class → Shield. Source files ≤ 400 lines (warning above 300), test files ≤ 600; a class ≤ 200 lines and ≤ 12 public methods. A long file is the larval form of a Manager class; splitting at 300 is cheap, at 1,200 it is a project. Waiver: same delete-only file, path.py or path.py:ClassName entries.

E · Types (3 gates)
QG-TYP-01 mypy 2.4.0, strict = true on core + records blocking · C (changed files), P, CI
Leaky Narrative → Filter. The record schema is the one contract between readers, miner, store and core; an untyped dict crossing it forces every caller to read the producer's source. Strict mode in the core makes the contract legible at the signature. numpy arrays carry numpy.typing.NDArray annotations.
QG-TYP-02 mypy 2.4.0, periphery: check_untyped_defs, warn_return_any, no_implicit_optional blocking · P, CI
Looser because periphery wraps third-party, often untyped, libraries (vizdoom, peft, mcp). ignore_missing_imports is allowed per-module in pyproject with a comment, never globally. hypothesis: whether pyright is swapped in later is open; the thresholds are tool-independent. Wired: already covered. The periphery settings are the global [tool.mypy] table (the core override only adds strict), so the QG-TYP-01 run in full is also this gate; run.sh names both ids on that line.
QG-TYP-03 no new # type: ignore (ratchet, scripts/ratchet/check.py) blocking · P, CI
Fossil Comments → Anchor. Every type: ignore must carry an error code and a reason (# type: ignore[arg-type] # vizdoom stubs lag 1.2.x); mypy's warn_unused_ignores deletes the ones that stop being needed. The count may only fall; baseline measured at adoption with an expiry. Wired as scripts/gates/check_type_ignores.py in fast (tokenizes, so a string is not a comment). Differs: the ratchet is the integer in scripts/gates/type-ignore-ceiling.txt (0 at adoption: the tree has none), not scripts/ratchet/check.py; raising it is a gate change under QG-GATE-01. A tree-wide check, so it holds changed files and the rest to the same bar at no cost.
F · Architecture boundaries (2 gates)
QG-ARC-01 import-linter 2.15 contracts in .importlinter blocking · P, CI
Infected Core → Buffer; Distributed Monolith → Shield. The name decides the tool: an Infected Core forms transitively (core → helper → store → sqlite3), and only an import-graph linter follows chains; semgrep sees one file. Contracts: (1) layers core above miner above records, lower never imports higher; (2) core forbids store, service, delivery, readers, eval, routeb, act1, wizard, cli and the external modules sqlite3, socket, http, urllib, requests, subprocess, vizdoom, transformers, peft, mcp with include_external_packages = True (without that flag externals are silently ignored and the contract passes forever); (3) routeb and act1 may import core and store, never eval's scoring internals, so a training script cannot read the grader; (4) eval may import core, never delivery (the grader must not call the live service). Waiver: ignore_imports with a comment, expiry-checked.
QG-ARC-02 existing boundary tests (tests/test_boundaries.py, tests/conftest.py) blocking · C (sub-second), P, CI
Already enforces the socket block for unmarked tests and the AST import rules on core measured: passing on 2026-10-27. Kept as the fast, dependency-free version of QG-ARC-01; both must agree. If they ever disagree, the test is wrong or the contract is wrong, never "both fine". Wired: already covered. tests/test_boundaries.py runs in every suite run (QG-TST-01) and in the pre-commit scoped set (QG-TST-02); its docstring carries the id.
G · Tests (6 gates)
QG-TST-01 pytest 9.1.1: test-count floor + zero skips blocking · C, P, CI
Paper Tiger → the gate must prove tests actually ran. A suite that collected 0 tests is green. scripts/gates/assert_suite_floor.py reads --junitxml, fails if tests < floor (floor = 240 at adoption, ratchets up to 95% of last green run, never down) or skipped > 0. Skips hide a dependency that should be a periphery mark or a fixture. Waiver: none; a test that cannot run is deleted or fixed.
QG-TST-02 coverage 7.17.0 via pytest-cov 7.1.0 blocking · P, CI
Core (line + branch) ≥ 90%; overall ≥ 75%; scripts/, spikes/, dashboard/ excluded. Two numbers because one global number lets the periphery dilute the core. fail_under lives in pyproject and only moves up (ratchet).
QG-TST-03 diff-cover 11.0.0 on changed lines blocking · P, CI
Paper Tiger → new public surface needs its first caller. Changed lines in src/ ≥ 90% covered, compared against main. Global coverage can stay flat while every new function ships untested; diff coverage cannot. Wired as scripts/gates/diff_coverage.sh in full, reading the XML of the same single coverage run as the suite. Untracked files are invisible to diff-cover; commit or stage before pre-push.
QG-TST-04 pytest-randomly 5.0.0 blocking · C, P, CI
Distributed Monolith inside the suite → Shield. Tests that pass only in file order share state. Seed printed on every run and re-usable with -p randomly -p "randomly_seed=N"; a failing seed goes in the bug report. Disable only per-test with a reason (@pytest.mark.order is not installed on purpose). Wired: -p randomly in the pytest addopts; run.sh picks the seed, prints QG-TST-04 seed=N (rerun: SYMBIONT_RANDOM_SEED=N) first in the suite output and passes it with --randomly-seed, so a red run carries its reproducer (-q hides the plugin's own header).
QG-TST-05 mutmut 3.8.0 on core release · R, weekly CI
Paper Tiger → tests that cannot fail. 90% core coverage with 40% mutants killed means the tests execute code without asserting on it. Threshold: ≥ 80% killed on core/ and miner/signals/; surviving mutants listed in the release notes. Runs before a scored run's tag and before publish, never in the inner loop (minutes, not seconds). hypothesis: mutmut 3.x config keys (paths_to_mutate, tests_dir) and the mutmut run / mutmut results CLI; verify against 3.8.0 docs before wiring. Wired as scripts/gates/mutation.sh with mutation_score.py: a manual and release target, deliberately not in run.sh. It runs fresh, prints the killed share (killed plus timeout over all mutants) and lists survivors; exit 1 below the bar, 2 if mutmut cannot run. Resolves the hypothesis: mutmut 3.8.0 reads source_paths and pytest_add_cli_args_test_selection (paths_to_mutate and tests_dir are deprecated aliases), and the whole src/symbiont package must be copied, with only_mutate narrowing what is mutated; a partial copy shadows the installed package. First measurement: measured 85.6% killed over 1741 mutants, about 5 minutes on the laptop under load.
QG-TST-06 no network, clock or disk in unit tests blocking · every stage
Infected Core → Buffer. Already in place: conftest.py raises AirplaneViolationError on any socket from an unmarked test. Extended by a tmp_path-only rule: unmarked tests that open a path outside tmp_path fail (pytest-socket is not added; the home-grown block is smaller and already tested). Waiver: @pytest.mark.periphery, which is a classification, not an exemption. Partly covered: the network part is tests/conftest.py plus tests/airplane.py (the id is in that docstring). The tmp_path-only disk rule and any clock rule named above are not enforced; see "Not wired yet".

I · Readability and maintainability (4 gates)
QG-RD-01 interrogate 1.7.0 docstring coverage on public API blocking · P, CI
Forensic Coding → Anchor. Public functions and classes in src/ ≥ 90% documented, private names excluded (--ignore-private --ignore-magic). The docstring states the why and the failure mode (what it raises), not a restatement of the signature; QG-RD-04 catches the latter. Wired as scripts/gates/check_docstrings.sh in full: the changed src/symbiont files must reach the bar together (phase 1 scope). The whole-tree figure is in baseline.json.
QG-RD-02 naming rules (scripts/gates/check_naming.py, AST) blocking · E, C, CI
Forensic Coding → Anchor; Leaky Narrative → Filter. Vague words are forbidden as whole snake_case or CamelCase parts of function, class and module names: handle, process, manage, do, run_it, helper, util(s), misc, data, info, stuff, Manager, Handler, Processor (dataset_rows passes, load_data fails). These names are where responsibilities go to hide. Single-letter names are forbidden except loop and comprehension targets, x, y and _. Also forbidden: a public function whose name is a tool name (sqlite_insert) rather than a capability (remember_pain_point) hypothesis: not mechanisable; a review item. Waivers, ratchets and exceptions

Every exception is a dated, owned, delete-only line in one enumerable place; ratchets move only toward stricter; break-glass is logged loudly and expires in 24 hours.

▶
  • Delete-only waiver files. .lizard-whitelist.txt, scripts/gates/audit_waivers.txt, scripts/gates/comment_waivers.txt. A test (tests/scripts/test_waivers_delete_only.py) diffs each file against main and fails on any added line. Editing the number must never be cheaper than fixing the code (Paper Tiger prevention).
  • Every entry carries owner · reason · expires YYYY-MM-DD. scripts/gates/check_expiries.py enumerates the two waiver directories (not a glob; a Fossil Comment hides in the file the glob forgot) and fails CI on the day after expiry, naming the entry, the owner and the one-line renewal path. Renewal = new date + updated reason in a reviewed commit, so an Anchor is left behind.
  • Ratchets (scripts/ratchet/baseline.json): test-count floor, coverage floors, type: ignore count, lizard offender count, ruff finding count on legacy paths. check.py --update rewrites downward only (upward for floors) and refuses to launder a regression. Each metric has an expiry at which it must reach its target or be renewed with a reason.
  • Break-glass. SYMBIONT_GATE_BYPASS="<gate-id>: <reason>" skips exactly one named gate for one invocation, prints a red banner, appends a line to .gate-bypass.log (tracked; its growth is a metric), and is forbidden for SEC-*, SCI-01 and TST-01, which have no bypass path at all. An unnamed bypass (SKIP_ALL) does not exist.
  • Who approves. Solo repo: the owner, in person, by editing the waiver file in a commit whose message says why. Agents may never add a waiver line (QG-AI-02 denies the write). Enterprise framing: the code owner of the path plus one reviewer outside the team for SEC and DEP waivers.

Scored-run prereg refusal (src/symbiont/eval/prereg.py, sketch)
class PreregNotFrozen(RuntimeError):
    """A scored run was requested without a frozen, committed pre-registration (QG-SCI-01)."""

def require_frozen_prereg(path: Path, repo_root: Path) -> str:
    """Return the sha256 of the prereg if it is FROZEN, tracked and unmodified; else raise.

    Why: a scored result without a prereg is a Silent Fallback at the claim level —
    the number looks measured but the hypothesis was free to move. Raising here, inside
    the runner, means no hook or script bypass can produce a scored row.
    """
    text = path.read_text()
    if "Status: FROZEN" not in text:
        raise PreregNotFrozen(f"{path}: status is not FROZEN")
    dirty = subprocess.run(["git", "status", "--porcelain", "--", str(path)],
                           cwd=repo_root, capture_output=True, text=True, check=True).stdout
    if dirty.strip():
        raise PreregNotFrozen(f"{path}: has uncommitted changes; commit it, then run")
    return hashlib.sha256(text.encode()).hexdigest()

Lives in eval/ (periphery: it calls git), tested with a temp repo under @pytest.mark.periphery. The runner writes the returned hash into results/*.json so a later prereg edit is detectable.
