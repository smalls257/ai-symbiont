# miner: pain points from records

See root CLAUDE.md for the repo rules. This file covers `src/symbiont/miner/`.

**Purpose.** Pure rules that turn a chain of `Record`s into `PainPoint`s (reworked edit, failed command, loop, correction, blast radius, review flag), find what resolved each (`resolutions.py`, `changes.py`), and build `Lesson`s (`lessons.py`): a pain point with its own bounded quote, resolution steps and `remote_safe` flag, so nothing downstream needs the records.

**Violation prevented: Black Box and God Class.** A pain point nobody can trace is a warning nobody can trust, so every `PainPoint` cites the `RecordRef`s it came from, and a note can quote them verbatim. One signal per file under `signals/`; `mine.py` is the only place that lists them, so adding a signal is one line.

## Invariants
- Pure over records: no I/O, no clock. A chain is one developer's sessions on one repo in run order; parallel attempts are chains of one.
- Signals do not import each other; shared helpers (`commands`, `diffs`, `failing_tests`) are small and named by capability.
- A signal that cannot decide returns nothing; it never invents a pain point.
- A resolution is what the history shows or a stated reason, never a guess. A failed command's fix is what changed between the failure and the later pass of the same command (same program, subcommand and target): installs, configuration, edits to a file the failure names, or a different invocation. "The same command" means the same program, subcommand and target, or the same *check* (`same_check.py`): a later clean pass whose tool matches (wrappers like `uv run`, `python -m`, `npx`, `bundle exec` peeled; `go test`/`cargo test` keep their subcommand) and whose targets are absent (a broader run) or overlap the failed run's (equal, path prefix, same file stem). It is language-agnostic on purpose, never parses a runner's output, and is loose: it may over-propose a lesson, and the delivery-time judge (agree rule, nightly judge) filters those; a run narrower than the failure, a different tool or disjoint targets never match. Pass/fail is the exit code plus the generic piped-output detector. The same command passing unchanged is no fix; an edit to a file the failure never names is reported alongside, never as the fix.
- A lesson needs a shown fix (`fixes.py`, `screen.py`): a failed command is taught only when the resolution's own steps edit the codebase, or the same program was run correctly after a wrong invocation (`failure_keys.INVOCATION_FAILURES`). A pass that only changed the arguments is `PASSED_RESPELLED`, never a resolution. Everything else is struggle: counted, shown on the dashboard, never a note. A fix is searched in the failure's own session only. `screen()` holds groups under one reason each (`IGNORED`, `NO_FIX_SHOWN`, `NO_MESSAGE`, `PROBE_COMMAND`, `THROWAWAY_SCRIPT`, `TOO_FEW_SESSIONS`); corrections, review flags and loops are never held. A failed-command group must show its fix in `min_sessions` sessions and a kept group keeps only the occurrences that show it. A script the session itself created (`Lesson.target_created`, from an `EDIT` tagged `created`, `created.py`) or an inline one is `THROWAWAY_SCRIPT`; location never decides, so `manage.py` stays. The match is on the full repo-relative path (`src/run.py` is not `lib/run.py`); only two paths outside the codebase match by bare file name, except under a temporary directory, which matches only its own full path (`/tmp/manage.py` is not the project's `manage.py`); a refused create made nothing. Rework is no longer a signal: `churn.py` counts applied edits per repo-relative file per session.
- The Pain points stage is decided here, not on the page (Violation prevented: Infected Core). `patterns.py` names eight ways a session's struggle looks (`StrugglePattern`, the help that fits each in `HELP`); `themes.py` finds what a session was about from the task text (first user turn or issue body, Claude Code's `ai-title` and `gitBranch` tags from `records.session_tags`) intersected with the codebase's own vocabulary (file stems and name parts seen 5+ times in codebase edits); `Codebase.contains` is `repo_relative`, never a second rule; `struggle.py` measures `turns_lost` (a failure to the next pass of the same program, spans merged, each capped) and files every failure's `Outcome` (its first two values are the `FixKind` values); `strips.py` and `representatives.py` pick and draw the few sessions the page shows. Every threshold says it was tuned once on sqlglot OpenHands traces and is re-measured, not retuned, without the owner. `MINUTES_PER_TURN` is a `[hypothesis]`.
- Plain words (Violation prevented: Leaky Narrative): `fix_words.fix_phrase` is the one place a fix is worded: base file names, never code or paths, at most one command named by program and subcommand, at most `PHRASE_CHARS` (110) characters. `Lesson.resolution` holds that phrase (a one-item tuple; twins pool several), and `Lesson.fix_commands` keeps the typed commands for the judge and training rows only. `working_command` is the one-line example of a command; `empty_correction` keeps "ok" and "/compact" from becoming corrections.
- A lesson's `remote_safe` is computed from every record it quotes, never defaulted; a missing cited record raises `LookupError`.
- No raw history leaves mining: a lesson keeps a quote of at most `QUOTE_CHARS` characters, never whole records.

- Must not import: core, store, readers, service, delivery (airplane test, import-linter).
